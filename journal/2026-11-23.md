## Taught — Scheduler: 3 key parts

Source: [`scheduler.py` `__init__`, pinned commit 6ba1050](https://github.com/vllm-project/vllm/blob/6ba10507e11c012d40051548c07c10c9bc5971d6/vllm/v1/core/sched/scheduler.py).

| Part | Type | Holds | Analogy (restaurant) |
| --- | --- | --- | --- |
| `waiting` | deque | Requests not started yet (and preempted ones) | Line at the door |
| `running` | list | Requests in the GPU batch now | Guests at tables |
| `kv_cache_manager` | manager | KV blocks: gives out / takes back | Host with the table list |

- The **Scheduler** decides who goes to `waiting` / `running`. `kv_cache_manager` only answers "blocks or no blocks" (`None`).
- `add_request()` → end of `waiting` (new request). `prepend_request()` → front (`appendleft`), used for a preempted request. `prepend` = 前置 / 加到最前面.

## Key correction

- Preemption is triggered **only** by a running request that needs one more block when there are no free blocks.
- A new waiting request that can't fit stays at the head of `waiting`.
- "New request kicks out a running one" = priority preemption — not fully supported yet (candidate Issue #40004).
