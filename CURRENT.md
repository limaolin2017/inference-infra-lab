## Latest session close (2026-11-17)

- **New fact:** KV per token = `2 × layers × KV heads × head_dim × bytes`; MHA / GQA / MQA differ only in KV head count (32 layers, head_dim 128, FP16: 512 / 128 / 16 KiB per token). vLLM reserves the leftover GPU memory as KV blocks at startup (slow allocation, fragmentation, fixed capacity for the Scheduler).
- **Gap:** `slot_mapping` arithmetic — offset used the quotient (2×), logical block used instead of physical, pos treated as 1-based.
